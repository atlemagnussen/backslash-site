SSH best practices

2021-02-05~6 min ssh cli encryption linux

Start using the secure shell as it was meant to be, secure.

TL;DR
  • Use public key authentication and disable password login in sshd_config: PasswordAuthentication no
  • Use ed25519 for your SSH keys: ssh-keygen -a 100 -t ed25519
  • Don't ignore the fingerprint changed messages if you get one

If you're ssh'ing home to your open port 22, you're done. Internet hacker factories continuously crawl the web for open SSH ports.

You can easily prove it yourself. Try this:

sh$ grep "Failed pass" /var/log/auth.log

and see if there's any occurrences. See this blogpost on tecmint.com to check out other ways, as it depends on your distro where you find the auth log.

Disable password over ssh

The problem with passwords is that they can be either guessed or too complex to walk around and remember. You can program your router to block multiple failed ssh attempts, and maybe you should, but there is a more convenient way to avoid the problem.

Enter public key authentication.

If you do this without setting up a key pair that your ssh server will accept, you will now be locked out forever.

Generate a key

sh# -a 100 = KDF rounds, makes brute forcing the passphrase slower
$ ssh-keygen -a 100 -t ed25519 -C "atle@laptop"
$ ssh-copy-id -i ~/.ssh/id_ed25519.pub user@server

Lock down sshd_config

/etc/ssh/sshd_configPasswordAuthentication no
PermitRootLogin no
PubkeyAuthentication yes

Restart the daemon with sudo systemctl restart sshd, and keep your current session open until you've verified that a new one works.
